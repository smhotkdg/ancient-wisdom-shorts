# 스토리형 대본 — 구조는 그대로, 말투는 이야기로

**영상 구조와 제작 방식은 바꾸지 않는다.** 장면 구성·클립(최대 6초)·자막·레이아웃·합성은 기존 그대로다.
바뀌는 것은 내레이션뿐: 정보를 나열하지 않고, 주인공 한 명이 겪는 이야기처럼 들리게 쓴다.

## 구조 (기존 그대로, docs/story-format.md)

| 구간 | beat | 내용 |
|---|---|---|
| 훅 | hook | ○○ + 과장 반응어 |
| 문제 | problem | 무엇이 왜 곤란했나 |
| 질문 | question | 제목의 질문 |
| 해결 | solution | 방법을 단계로 (1~3장면) |
| 반전 | twist | 새로 생긴 의문 하나 |
| 마무리 해결 | resolve | 그 의문을 푸는 디테일 |
| 정리 + 정보 | info | 한 문장 답 + 오늘과 연결 |

## 마지막 대사 = 정답 공개 ("오! 이거였구나")

이야기 끝에서 이름을 공개해, 시청자가 "아, 그게 이거였어?" 하게 만든다.

- **마지막 대사는 "이것이 바로 ○○입니다" 형태**: "이 나무판이 바로 팔만대장경, 이 집이 바로 해인사 장경판전입니다."
  "그 돌 냉장고가 바로, 석빙고입니다." / "이 감자가 바로 추뇨입니다."
- **이름(○○)은 마지막까지 아낀다**: 대본 앞부분과 화면 제목에 정답 이름을 쓰지 않는다. "돌로 만든 얼음 창고", "땅속 물길", "나무판 8만 장"처럼 풀어서 부른다.
  (유튜브 제목·설명에는 검색을 위해 이름을 써도 된다.)
- 정답 이름은 `story.reveal`에 적는다 (여러 개면 목록). `aw.py story`가 마지막 대사 형태와 이름 숨김을 점검한다.
- 공개 직전 대사는 오늘과 연결(지금도 남아 있다, 몇 년을 지켰다)로 여운을 만든다.
- 연출상 대본 구조(훅→…→정보)는 그대로이고, 정보 비트의 마지막 줄이 공개 대사가 된다.

## 화면은 주인공 중심 (2026-10-16 사용자)

인물이 너무 많아지면 영상 집중도가 떨어진다 (008 케스와차카: 마을 사람·군중·잔치 장면이 많아 산만했다).
하지만 모든 장면에 주인공 한 명만 둘 필요는 없다 — 장면에 잘 맞으면 배경 인물이 있어도 좋다
(좋은 예: 007 s08 — 관리가 가운데서 곡식 자루를 세고, 뒤에서 농부 몇 명이 어깨를 늘어뜨림).

- **주인공은 늘 가운데, 가장 크게.** 배경 인물은 뒤쪽에 작게, 몇 명만 (2~4명). 주인공을 가리지 않게.
- **배경 인물은 이야기에 반응하는 역할일 때만**: 세금에 한숨 쉬는 농부, 다리를 보고 놀라는 사람처럼 대사와 직접 연결될 때.
- **군중이 주인공인 장면은 만들지 않는다**: 줄지어 밧줄 당기는 마을 사람들, 잔치, 대규모 작업 현장 등.
- 배경 인물 장면은 **에피소드당 3개 이하**. 나머지는 주인공 혼자·클로즈업·결과물·풍경·단면도로.
- 프롬프트: 배경 인물이 있으면 "the hero in the center foreground, a few <people> in the background, smaller",
  주인공만 있으면 "No other people.", 사람이 없으면 "No people."
- 내레이션 주어는 주인공으로 쓴다. 실제로는 여럿이 했다는 점은 `accuracy_notes`에 적는다.
- 주제를 고를 때도 **한 사람이 끌고 갈 수 있는 이야기**를 우선한다.
- `aw.py story`가 배경 인물 장면(villagers, workers, crowd, farmers, family, people… / 사람들·일꾼·가족)을 세어 3개를 넘으면 실패로 알린다.

## 이야기처럼 들리게 쓰는 법

- **주인공 한 명을 따라간다**: 역할 이름(빙고지기, 썰매꾼, 장인)으로 부르고, 해결 단계도 그 사람이 하는 행동으로 쓴다.
  - 나열: "먼저, 땅을 파고 반지하로 지었습니다."
  - 이야기: "빙고지기는 먼저 땅을 깊이 팠습니다. 땅속은 한여름에도 서늘했거든요."
- **나열어 금지**: "첫째·둘째·셋째", "먼저,"로 시작하는 목록식 문장 대신 행동과 이유로 잇는다.
- **전환어로 다음이 궁금하게**: 그런데 · 하지만 · 그때 · 그래서 · 드디어.
- **감정 한두 줄**: 문제 앞에서의 반응, 해결 뒤의 안도 ("이번엔 버틸까?", "드디어 해냈죠").
- **눈에 보이는 장면으로 말한다**: 숫자·용어보다 화면에 나오는 행동(물을 붓는다, 짚을 채운다).
- **사실과 연출 구분**: 주인공·감정·대사는 설명용 재구성이다. 구조·원리·연대는 근거 있는 것만.
  `accuracy_notes`에 "인물과 장면은 재구성"을 적고, "기록에 따르면" 같은 지어낸 인용, 실제 이름·날짜는 쓰지 않는다.

## 유튜브 설명 (youtube.txt)

설명도 이야기처럼, 짧고 재미있게 쓴다. `python aw.py youtube <ep>`로 확인.

- **첫 줄 = 궁금증**: 이모지 1개 + 질문이나 상황 한 줄 ("🧊 한겨울 얼음, 한여름까지 버틸 수 있을까요?")
- **본문 2~4줄**: 주인공이 무엇으로 해결했는지 맛보기. 리듬 있는 나열·비유 OK ("짚과 왕겨 이불", "돌 냉장고").
  반전의 답은 다 말하지 말고 살짝 남긴다.
- **마지막 줄 = 오늘과 연결**: 지금도 볼 수 있는 곳, 의외의 사실 하나.
- **comment_question**: 시청자가 답하고 싶은 질문 하나 ("여러분이라면 어떻게?")
- 이모지는 전체 3~4개까지. 과장은 연출 수준만, 사실 수치는 근거 있는 것만.
- "재구성한 애니메이션입니다" 안내는 `config/project.yaml`의 `youtube.disclaimer`가 자동으로 붙으니 본문에 쓰지 않는다.

## episode.yaml

`story.hero`에 주인공을, 각 장면에 `beat:`를 적고 `python aw.py story <ep>`로 점검한다.

```yaml
story:
  hero: 빙고지기
  reveal: [석빙고]     # 마지막 대사에서 공개할 이름 — 그 전에는 대본·화면 제목에 쓰지 않는다
scenes:
  - id: s01
    beat: hook      # hook | problem | question | solution | twist | resolve | info
```
